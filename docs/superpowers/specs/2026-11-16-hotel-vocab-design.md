# เว็บคำศัพท์งานโรงแรม (อังกฤษ–จีน) — Design

วันที่: 2026-11-16 · สถานะ: อนุมัติแล้ว (2026-11-16) · เจ้าของโครงงาน: ผู้ใช้ (ดูแลเองคนเดียว)

## 1. ทำไมต้องมีเว็บนี้

โครงงานเล็กๆ เป็นเว็บคำศัพท์และประโยคสำหรับงานโรงแรม ภาษาไทย / อังกฤษ / จีน / พินอิน
เจ้าของจะทำ QR code ของลิงก์เว็บ ตกแต่งเป็นโปสเตอร์ แล้วไปแปะที่แผนกการเรียนศิลป์-ภาษา
คนที่เดินผ่านหรือนักเรียนจะสแกนด้วยมือถือของตัวเอง แล้วเปิดดูคำศัพท์

ผลที่ต้องการ: สแกนแล้วเปิดได้ทันที อ่านง่ายบนมือถือ เห็นครบทุกภาษา และฟังเสียงอ่านได้

## 2. เป้าหมาย / สิ่งที่ไม่ทำ / สิ่งที่ห้ามเกิด

**เป้าหมาย**
- สแกน QR แล้วเห็นหน้าแรกเร็วบนเน็ตมือถือ (เว็บเบา ไม่มี framework ไม่มีรูปหนัก)
- เลือกหมวด 1 ใน 4 หมวด แล้วเห็นคำศัพท์ทั้ง 15 คำ ครบทั้ง 4 ภาษา โดยไม่ต้องแตะเพิ่ม
- ฟังเสียงอ่านภาษาอังกฤษและจีนได้ ถ้ามือถือเครื่องนั้นรองรับ
- ลิงก์ใช้ได้ถาวร แก้คำศัพท์ทีหลังได้โดยไม่ต้องพิมพ์ QR ใหม่
- เจ้าของแก้หรือเพิ่มคำศัพท์ได้ง่าย โดยแก้ไฟล์ข้อมูลไฟล์เดียว

**สิ่งที่ไม่ทำ (non-goals)**
- ไม่มีล็อกอิน ระบบหลังบ้าน หรือฐานข้อมูล
- ไม่มีช่องค้นหา แบบทดสอบ แฟลชการ์ด หรือการบันทึกคำโปรด
- ไม่มีโหมดมืด ไม่ทำให้ใช้ออฟไลน์ได้ (PWA) และไม่ใช้โดเมนของตัวเอง
- ไม่อัดไฟล์เสียงไว้ล่วงหน้า (ใช้เสียงที่มีในเครื่องแทน)
- ไม่ได้ทำ QR code และโปสเตอร์ให้ (เจ้าของทำเอง)

**สิ่งที่ห้ามเกิด (anti-goals)**
- ลิงก์เปลี่ยนหรือใช้ไม่ได้ หลังจากพิมพ์ QR ไปแล้ว
- เว็บถูกระงับเพราะโควตาของที่ฝากเว็บหมด
- มีปุ่มฟังเสียงที่กดแล้วไม่มีเสียง (ถ้าไม่รองรับ ต้องซ่อนปุ่ม ไม่ใช่ปล่อยให้กดแล้วเงียบ)
- ข้อความภาษาไทยมีสระหรือวรรณยุกต์เพี้ยน (ข้อความที่ดึงจาก PDF เพี้ยนอยู่ ห้ามคัดลอกมาตรงๆ)

## 3. ข้อจำกัด

- เทคโนโลยีที่เจ้าของกำหนด: HTML + Tailwind CSS (CLI) + JavaScript ล้วน (ไม่ใช้ framework)
- ต้องออกแบบสำหรับมือถือก่อน (ทดสอบที่ความกว้าง 360px ขึ้นไป)
- ต้องใช้งานได้ใน iPhone Safari, Android Chrome และ**เบราว์เซอร์ในแอป LINE** (คนไทยสแกน QR ผ่าน LINE กันเยอะ)
- ที่ฝากเว็บ: Cloudflare Pages แบบเชื่อมกับ GitHub (เปลี่ยนเป็นแบบอัปโหลดเองทีหลังไม่ได้ และเปลี่ยนจากแบบอัปโหลดเองมาเป็นแบบนี้ก็ไม่ได้ เพราะต้องสร้างโปรเจกต์ใหม่ = ได้ลิงก์ใหม่)
- โฟลเดอร์โปรเจกต์บนเครื่องเจ้าของ: `C:\khem`
- เครื่องของเจ้าของต้องมี Node.js (LTS) และ Git ไว้แก้เว็บและ push ขึ้นไป

## 4. ทางเลือกที่พิจารณา (Approaches)

**ที่ฝากเว็บ** — เลือก Cloudflare Pages
- Cloudflare Pages: ฟรี ไม่จำกัดจำนวนครั้งที่คนเปิดเว็บกับปริมาณข้อมูล ตั้งชื่อลิงก์เองได้ (`<ชื่อ>.pages.dev`) ← **เลือก** เพราะลิงก์สั้น (QR มีจุดน้อย สแกนง่าย) ไม่ผูกกับชื่อบัญชี และไม่โดนระงับเพราะคนเข้าเยอะ
- GitHub Pages: ฟรี แต่ลิงก์มีชื่อบัญชีอยู่ในนั้น ถ้าเปลี่ยนชื่อบัญชีลิงก์จะเปลี่ยนตาม และแบบฟรีโค้ดต้องเปิดให้คนอื่นดูได้
- Netlify: แพ็กเกจฟรีมี 300 เครดิตต่อเดือน ถ้าหมดเว็บทั้งบัญชีจะถูกปิด เสี่ยงเกินไปสำหรับลิงก์ที่อยู่หลัง QR

**วิธีอัปเดตเว็บ** — เลือกเชื่อมกับ GitHub
- เชื่อม GitHub: push แล้ว Cloudflare สร้างเว็บและอัปเดตให้เอง มีสำรองโค้ดและประวัติการแก้ไข ← **เลือก** (เจ้าของใช้ GitHub เป็น)
- อัปโหลดเอง: ไม่ต้องใช้ git แต่โค้ดอยู่ในเครื่องที่เดียว

**เสียงอ่าน** — เลือกใช้เสียงที่มีในเครื่อง
- เสียงในเครื่อง (Web Speech API): ฟรี เว็บเบา แต่บางเครื่องไม่มีเสียงจีน และในเบราว์เซอร์ของ LINE บน Android อาจไม่มีเสียงเลย ← **เลือก**
- อัดไฟล์เสียงไว้ล่วงหน้า (120 ไฟล์): เสียงเหมือนกันทุกเครื่อง แต่ต้องหาวิธีทำไฟล์ และเว็บหนักขึ้น (เก็บไว้เป็นทางอัปเกรดทีหลัง)
- ไม่มีเสียง

**หน้าตาหน้าคำศัพท์** — เลือกแบบ A การ์ดเต็ม
- A การ์ดเต็ม: เห็นครบ 4 ภาษาโดยไม่ต้องแตะ ← **เลือก**
- B รายการสั้น: ต้องแตะทีละคำถึงจะเห็นภาษาจีน
- C แฟลชการ์ด: ดูทีละคำ ถ้าจะไปคำที่ 12 ต้องกดถัดไปหลายครั้ง

**โครงสร้างโค้ด** (ผมตัดสินใจเอง) — HTML หน้าเดียว ใช้ JavaScript สลับระหว่างหน้าแรกกับหน้าหมวด และคำศัพท์อยู่ในไฟล์ข้อมูลไฟล์เดียว
ทางอื่นที่พิจารณาคือทำ HTML 5 ไฟล์แยกกัน ไม่เลือก เพราะข้อมูลจะซ้ำกันหลายที่ แก้คำศัพท์ทีเดียวต้องแก้หลายไฟล์

## 5. สิ่งที่เจ้าของตัดสินใจแล้ว

### ข้อมูล
- มี 4 หมวด หมวดละ 15 รายการ รวม 60 รายการ แต่ละรายการมี: ไทย, อังกฤษ, จีน, พินอิน
- ชื่อหมวด (จาก Excel ต้นฉบับ):
  1. การต้อนรับและเช็คอิน — Reception & Check-in
  2. แม่บ้านและสิ่งอำนวยความสะดวกในห้อง — Housekeeping & Room Amenities
  3. บริการทั่วไปและสิ่งอำนวยความสะดวกส่วนกลาง — Hotel Facilities & Services
  4. การแจ้งปัญหาและการเช็คเอาท์ — Problem Solving & Check-out
- แหล่งข้อมูล: PDF `Hotel_Vocabulary_TH_EN_CN.pdf` (ใช้ได้กับอังกฤษ/จีน/พินอิน) และภาพหน้าจอ Excel 4 หมวด (ใช้ข้อความภาษาไทยจากภาพนี้ เพราะภาษาไทยใน PDF เพี้ยน)
- เรียงลำดับตามไฟล์ Excel

### หน้าแรก
- หัวเว็บ: "คำศัพท์งานโรงแรม" บรรทัดรอง: "อังกฤษ · จีน · พินอิน"
- มีปุ่มหมวด 4 ปุ่ม แต่ละปุ่มแสดง: เลข 01–04 (สีแดง), ชื่อไทย, ชื่ออังกฤษ, "15 คำ" และลูกศรขวา

### หน้าหมวด (แบบ A การ์ดเต็ม)
- ด้านบนมีปุ่มย้อนกลับกับ "01 ชื่อหมวด" และแถบนี้ค้างอยู่บนจอตอนเลื่อน
- มีการ์ด 15 ใบ แต่ละใบมี:
  - บรรทัดเล็กสีเทา: "ลำดับ · ภาษาไทย"
  - ภาษาอังกฤษ และปุ่มฟังเสียงอยู่ด้านขวา
  - ภาษาจีนตัวใหญ่ ใต้ลงมาเป็นพินอินสีแดง และปุ่มฟังเสียงอยู่ด้านขวา
- ท้ายหน้ามีปุ่ม "หมวดถัดไป" (หมวด 4 เป็นปุ่ม "กลับหน้าแรก" แทน)

### เสียงอ่าน
- อังกฤษใช้สำเนียงอเมริกัน (`en-US`) ถ้าไม่มีใช้ `en-*` ตัวอื่น
- จีนใช้จีนกลาง (`zh-CN`) ถ้าไม่มีใช้ `zh-TW` ห้ามใช้ `zh-HK` เพราะเป็นภาษากวางตุ้ง
- ถ้าเครื่องไม่มีเสียงภาษาไหน ซ่อนปุ่มของภาษานั้นทั้งเว็บ ถ้าเบราว์เซอร์ไม่รองรับเลย ซ่อนทุกปุ่ม
- คำที่มี " / " ให้อ่านทั้งสองคำ โดยแทน "/" ด้วยการเว้นจังหวะ (อังกฤษใช้ ", " จีนใช้ "，") เพื่อไม่ให้เครื่องอ่านออกเสียงว่า "slash"

### ธีม
- มินิมอล พื้นขาว ใช้สีแดงเป็นสีหลัก (เส้นขอบแดงอ่อน ตัวเลข/พินอิน/ไอคอนแดง หัวข้อแดงเข้ม) ทำแค่ธีมสว่าง
- ภาษาไทยใช้ Noto Sans Thai (โหลดจาก Google Fonts แค่น้ำหนัก 400 และ 500 พร้อม `display=swap` เพื่อให้ตัวหนังสือขึ้นก่อนฟอนต์โหลดเสร็จ) ภาษาจีนใช้ฟอนต์ที่มีในเครื่อง

### ที่ฝากเว็บ
- Cloudflare Pages เชื่อมกับ GitHub repo ของเจ้าของ
- ลิงก์: `<ชื่อโปรเจกต์>.pages.dev` — **ชื่อโปรเจกต์: `hotel-vocab` (เจ้าของยืนยันแล้ว)**

## 6. รายละเอียดที่ผมตัดสินใจเอง (เจ้าของแก้ได้)

- **ลิงก์ของแต่ละหน้า:** ใช้ hash เช่น `#/` เป็นหน้าแรก, `#/c/1` ถึง `#/c/4` เป็นหน้าหมวด
  - ปุ่มย้อนกลับของมือถือใช้ได้ และแต่ละหมวดมีลิงก์ของตัวเอง
  - ถ้า hash ไม่ถูกต้องให้ไปหน้าแรก
  - เปลี่ยนหน้าแล้วเลื่อนจอขึ้นบนสุด และเปลี่ยนชื่อแท็บเป็นชื่อหมวด
- **โครงสร้างไฟล์:**
  ```
  public/index.html          หน้าเว็บ (โฟลเดอร์นี้คือสิ่งที่ Cloudflare เอาขึ้นเว็บ)
  public/js/app.js           สลับหน้า + สร้างหน้าจอจากข้อมูล
  public/js/speech.js        เสียงอ่าน
  public/js/data.js          คำศัพท์ทั้งหมด (แก้ไฟล์นี้ไฟล์เดียวพอ)
  public/favicon.svg
  public/styles.css          ← Tailwind สร้างให้ตอน build (ไม่เก็บใน git)
  src/input.css              ไฟล์ตั้งค่า Tailwind + สีของธีม
  tests/                     ทดสอบด้วย node:test
  docs/superpowers/specs/    เอกสารนี้
  ```
- **Tailwind:** ใช้ Tailwind CLI เวอร์ชันล่าสุด (ตอนนี้คือ v4 แพ็กเกจ `@tailwindcss/cli` ให้ตรวจเวอร์ชันอีกครั้งตอนติดตั้ง)
- **คำสั่งใน `package.json`:**
  - `npm run dev`: Tailwind watch + เปิดเว็บในเครื่องไว้ดูตัวอย่าง
  - `npm run build`: สร้าง `public/styles.css` แบบย่อขนาด
  - `npm test`: รันชุดทดสอบ
- **ตั้งค่า Cloudflare Pages:**
  - Build command: `npm run build`
  - Output directory: `public`
  - กำหนดเวอร์ชัน Node ผ่าน `NODE_VERSION` ถ้าจำเป็น
- **JavaScript:** ใช้ ES modules (`<script type="module">`) ไม่มี framework ไม่ต้อง bundle
- **ความเร็วในการเสียงอ่าน:** อังกฤษ 0.9 จีน 0.8 (ช้ากว่าปกติเล็กน้อย เหมาะกับคนกำลังเรียน)
- **การเล่นเสียง:** กดปุ่มใหม่แล้วตัดเสียงเดิม ระหว่างที่กำลังอ่าน ปุ่มเปลี่ยนสีให้รู้ว่ากำลังเล่น
- **รายการเสียงในเครื่อง:** โหลดช้าในบางเบราว์เซอร์ ให้รอ event `voiceschanged` ไม่เกินประมาณ 1.5 วินาที ถ้ายังไม่มีเสียงก็ซ่อนปุ่ม
- **การเข้าถึง (accessibility):**
  - ปุ่มฟังเสียงมี `aria-label` ภาษาไทย เช่น "ฟังเสียงภาษาจีน: 欢迎光临我们酒店"
  - พื้นที่กดอย่างน้อย 44×44px และสีตัวอักษรตัดกับพื้นตามมาตรฐาน WCAG AA
  - ใส่ `lang` ให้ข้อความแต่ละภาษา (`th` / `en` / `zh-CN`) เพื่อให้เครื่องเลือกฟอนต์และอ่านถูกภาษา
- **meta:** `lang="th"`, viewport, `theme-color` สีแดง (แถบเบราว์เซอร์บน Android จะเป็นสีแดง), title, description และ favicon SVG สีแดงแบบเรียบ
- **GitHub repo:** แนะนำตั้งเป็นแบบส่วนตัว (private) เจ้าของเปลี่ยนเองได้
- **สถิติคนเข้าเว็บ (ไม่บังคับ):** เปิด Cloudflare Web Analytics ได้จากหน้าตั้งค่าโปรเจกต์ ไม่ต้องแก้โค้ด

## 7. การทดสอบ

- **ทดสอบอัตโนมัติ (`npm test`):**
  - ข้อมูลครบ 4 หมวด หมวดละ 15 รายการ ทุกช่องไม่ว่าง และ id ไม่ซ้ำ
  - ภาษาไทยไม่มีสระลอยผิดตำแหน่ง (เช่น ไม่มีช่องว่างหน้าสระบน/ล่าง)
  - ฟังก์ชันแปลง " / " ก่อนส่งให้เสียงอ่าน
  - ฟังก์ชันแปลง hash เป็นหน้า
- **ทดสอบด้วยตาในเบราว์เซอร์ขนาดมือถือ (360px และ 390px):** ทั้ง 5 หน้า, การเลื่อน, แถบด้านบนที่ค้างอยู่, ปุ่มย้อนกลับ และปุ่มหมวดถัดไป
- **ตรวจข้อมูล:** เทียบข้อมูลทั้ง 60 รายการกับภาพหน้าจอ Excel
- **หลัง deploy เจ้าของต้องทดสอบบนมือถือจริง:** iPhone Safari, Android Chrome และเปิดผ่าน LINE (ทั้ง iPhone และ Android) — ดูว่าปุ่มเสียงขึ้นหรือซ่อนถูกต้อง

## 8. ขั้นตอน deploy (ทำครั้งเดียว)

1. เจ้าของสร้าง GitHub repo แล้ว push โค้ดจาก `C:\khem` ขึ้นไป
2. ใน Cloudflare dashboard ไปที่ Workers & Pages → สร้าง Pages project → เชื่อม Git → เลือก repo → ตั้งชื่อโปรเจกต์ (ชื่อนี้จะกลายเป็นลิงก์) → ใส่ build command และ output directory ตามข้อ 6
3. เปิดลิงก์ `.pages.dev` แล้วทดสอบบนมือถือ **ก่อน**ทำ QR
4. หลังจากนี้ แก้ไขแล้ว push → เว็บอัปเดตเอง ลิงก์เดิม

หมายเหตุ: ถ้าชื่อโปรเจกต์ที่ต้องการมีคนใช้ไปแล้ว Cloudflare จะเติมตัวอักษรท้ายชื่อให้ ให้ดูลิงก์จริงหลังสร้างโปรเจกต์ แล้วเอาลิงก์นั้นไปทำ QR

## 9. สิ่งที่เหลือให้คนสร้างตัดสินใจ

- ระยะห่าง ขนาดตัวอักษร และเฉดสีแดงที่แน่นอน (ให้ตรงกับ mockup ที่เจ้าของเลือก)
- ไอคอนลำโพงและลูกศร (ใช้ SVG ฝังในหน้าเว็บ ไม่โหลดชุดไอคอนทั้งชุด)
- รายละเอียดของเซิร์ฟเวอร์สำหรับดูตัวอย่างในเครื่องตอน `npm run dev`
