# รองรับทุกขนาดจอ (มือถือ / iPad / PC) — Design (งานแก้เล็ก)

วันที่: 2026-11-17 · สถานะ: อนุมัติแล้ว (2026-11-17) · ต่อยอดจาก `2026-11-17-colors-and-thai-size-design.md`

## ทำไม
เจ้าของอยากให้เว็บใช้ได้ดีบน PC และ iPad ด้วย ไม่ใช่แค่มือถือ ตอนนี้ทั้งหน้าถูกบีบไว้ในกล่องกว้าง 448px (`max-w-md` ที่ `#app`) บนจอกว้างแถบน้ำเงินจึงดูหดสั้นผิดปกติ จากตัวอย่างที่เห็น เจ้าของบอกว่าการ์ดแต่ละคอลัมน์ "ยืดและเบียดกันเกินไป" และปุ่มหมวดถัดไปที่อยู่กลางจอ "ดูแปลก" และย้ำว่าต้อง "รองรับได้ทุกรูปแบบ"

## เป้าหมาย / ไม่ทำ / ห้ามเกิด
- **เป้าหมาย:**
  - แถบน้ำเงินเต็มความกว้างจอทุกขนาด
  - การ์ดคำศัพท์เรียงเป็นตาราง โดยจำนวนคอลัมน์คำนวณจากความกว้างจอเอง
  - การ์ดมีระยะห่างพอ ไม่เบียด ไม่ยืด
  - ท้ายหน้าเป็นแถวปุ่มซ้าย-ขวา
- **ไม่ทำ:** ไม่เปลี่ยนสี ขนาดตัวหนังสือ ข้อมูล เสียงอ่าน หรือการเปลี่ยนหน้า และหน้ามือถือ (<640px) ต้องหน้าตาเหมือนเดิม
- **ห้ามเกิด:**
  - การ์ดแคบกว่าประมาณ 280px
  - ข้อความล้นจอที่ขนาดใดก็ตาม
  - แถบน้ำเงินไม่เต็มจอ
  - iPad mini แนวตั้ง (744px) ได้คอลัมน์เดียวแคบๆ กลางจอ

## ทางเลือก (Approaches)
- **ตาราง `auto-fill` ที่กำหนดความกว้างการ์ดขั้นต่ำ** ← **เลือก**
  - เขียนเป็น `grid-cols-[repeat(auto-fill,minmax(min(100%,18rem),1fr))]`
  - เบราว์เซอร์ใส่คอลัมน์ให้มากที่สุดเท่าที่การ์ดยังกว้าง ≥ 18rem (288px) ได้ จึงรองรับทุกขนาดจอโดยไม่ต้องไล่ตั้งเกณฑ์ทีละขนาด
- **ตั้งเกณฑ์ตายตัว** (`md:` = 2 คอลัมน์, `lg:` = 3 คอลัมน์): จอที่อยู่ระหว่างเกณฑ์จะดูไม่พอดี เช่น iPad mini 744px ได้คอลัมน์เดียว (เจ้าของเห็นตัวอย่างแล้วไม่โอเค)
- **Container queries:** ซับซ้อนเกินจำเป็นสำหรับหน้าที่มีตารางเดียว

## หน้าตาที่เปลี่ยน (เจ้าของเห็นตัวอย่าง iPad แนวตั้งแล้ว และโอเค)
- **`#app`:** เอา `max-w-md` ออก ให้แต่ละหน้าจัดความกว้างเอง
- **แถบน้ำเงินทั้งสองหน้า:** พื้นเต็มความกว้างจอ เนื้อหาข้างในอยู่ในกล่องเดียวกับเนื้อหาด้านล่าง ขอบซ้ายจึงตรงกัน
- **หน้าแรก:**
  - กล่องกว้างไม่เกิน `max-w-3xl` (768px) อยู่กลางจอ
  - ปุ่มหมวดเรียง 1 คอลัมน์บนมือถือ และ 2 คอลัมน์ (2×2) ตั้งแต่ 640px (`sm:`)
- **หน้าหมวด:**
  - กล่องกว้างไม่เกิน `max-w-6xl` (1152px) ขอบซ้ายขวา `px-4` และ `sm:px-6`
  - การ์ดเรียงด้วยตาราง `auto-fill` ข้างบน ระยะห่าง `gap-3` บนมือถือ และ `sm:gap-5` (20px) บนจอที่กว้างกว่า
  - การ์ดในแถวเดียวกันสูงเท่ากัน (ค่าปกติของ grid) ขอบในการ์ดเพิ่มจาก `px-4 py-3` เป็น `sm:px-5 sm:py-4`
  - **จำนวนคอลัมน์ที่คาดไว้** (ขอบสองข้างรวม 48px บนจอ ≥ 640px):

    | ขนาดจอ | คอลัมน์ |
    |---|---|
    | มือถือ 390 | 1 |
    | iPad mini 744 / iPad 820 (แนวตั้ง) | 2 |
    | iPad Pro 1024 (แนวตั้ง) | 3 |
    | 1133 / 1180 / 1366 / 1440 | 3 |

- **ท้ายหน้าหมวด:**
  - **มือถือ:** เหมือนเดิม
    - หมวด 1–3: ปุ่ม "หมวดถัดไป" เต็มความกว้าง
    - หมวด 4: ปุ่ม "กลับหน้าแรก" เต็มความกว้าง
  - **ตั้งแต่ 640px:** แถวเดียว ซ้ายเป็น "← หน้าแรก" (ขอบส้ม พื้นขาว) ขวาเป็นปุ่ม "หมวดถัดไป" สีส้มเข้ม กว้างไม่เกิน `max-w-md`
  - **ตั้งแต่ 640px หมวด 4:** มีแค่ "← หน้าแรก" อยู่ทางซ้าย

## การทดสอบ
- **`tests/views.test.js`:**
  - หน้าหมวดใช้คลาสตาราง `auto-fill` (ตรวจแบบทั้งคำด้วย `hasClass`)
  - หมวด 1–3 มีทั้งลิงก์ไป `#/` และลิงก์ไปหมวดถัดไปในท้ายหน้า
  - `index.html` ไม่มี `max-w-md` ที่ `#app`
- **`check.py`** ตรวจที่ 8 ขนาด ได้แก่ 390×844, 744×1133, 1133×744, 820×1180, 1180×820, 1024×1366, 1366×1024 และ 1440×900 ทุกขนาดต้องผ่านทุกข้อนี้:
  - ไม่ล้นแนวนอน
  - แถบน้ำเงินกว้างเท่าจอ
  - จำนวนคอลัมน์ตรงตามตาราง
  - การ์ดทุกใบกว้าง ≥ 280px
  - ตั้งแต่ 640px ปุ่ม "← หน้าแรก" อยู่ซ้ายของปุ่ม "หมวดถัดไป" ในแถวเดียวกัน
  - การตรวจเดิมทั้งหมดยังต้องผ่าน
- **ภาพหน้าจอ:** ถ่ายครบ 8 ขนาด แล้วส่งให้เจ้าของดู

## สิ่งที่ผมตัดสินใจเอง (แก้ได้)
- ใช้ 18rem เป็นความกว้างขั้นต่ำของการ์ด
- จำกัดความกว้างหน้าหมวดที่ `max-w-6xl` และหน้าแรกที่ `max-w-3xl`
- เกณฑ์ 640px (`sm:`) ใช้สำหรับปุ่มหมวด 2×2 และแถวปุ่มท้ายหน้า
- ปุ่ม "← หน้าแรก" ด้านซ้ายเป็นปุ่มใหม่ เพื่อไม่ให้ปุ่มหมวดถัดไปดูลอยอยู่ข้างเดียว

## แก้หลังตรวจทาน (2026-11-17)
- **ปัญหาเดิม:** จอ 640–659px ซึ่งรวมหน้าต่าง Windows ที่มีแถบเลื่อนและจัดไว้ครึ่งจอ 1280px ได้การ์ดคอลัมน์เดียวกว้างเกือบ 600px ซึ่งคือการ์ดยืดแบบที่เจ้าของไม่ต้องการ ส่วนที่ 620–639px กลับได้ 2 คอลัมน์
- **ตารางการ์ด:** เปลี่ยนเป็น `grid sm:grid-cols-[repeat(auto-fill,minmax(17.5rem,1fr))]`
  - ต่ำกว่า 640px เป็นคอลัมน์เดียวเสมอ (แบบมือถือ)
  - ตั้งแต่ 640px การ์ดกว้างขั้นต่ำ 280px
- **ขอบข้างของการ์ด แถบ และปุ่มท้ายหน้า:** ใช้ 16px จนถึง 767px และ 24px ตั้งแต่ 768px (`md:px-6`) ทำให้ 640px ได้ 2 คอลัมน์แม้มีแถบเลื่อน
- **จำนวนคอลัมน์ใหม่:**

  | ความกว้างจอ (px) | คอลัมน์ |
  |---|---|
  | 390, 600, 630 | 1 |
  | 640, 744, 820 | 2 |
  | 1024 ขึ้นไป | 3 |

- **การตรวจแถบติดค้าง:** ย้ายไปตรวจที่ 1366×600 แบบมีปุ่มเสียง หน้าจะเลื่อนได้จริง
